# Settings

Loaded by `/gam-engineering settings [ask | auto | <key> <value>]` (skill `gam-setup`). It shows or changes the project's merge and model settings in `.claude/settings.json`, keeping the safeguards in step. It runs only when the developer invokes it — an agent never loosens a setting on its own initiative.

| Invocation | Effect |
| --- | --- |
| `settings` | Show the branch model (P-GIT-9), the effective values (after the team-mode and fallback rules of P-MR-4 and P-MR-5), the main model, the three tiers and the plan key (with the suffixed keys of other agents), and the session threshold ([Models](../../gam-engineering/references/models.md)), whether the merge guard and the status hook are present, the flow (`quick` or `full`), the plans folder (`plansDirectory`, P-DOC-7), whether commits and MRs credit the AI (`attribution`, P-GIT-8), the project kind and every key with its layer from `node gam-engineering/tools/project-settings.mjs show` (a personal value from `.claude/settings.local.json`, and a project key there that is ignored), and any instruction in `~/.claude/CLAUDE.md` that would override them. Changes nothing. |
| `settings auto` | Preset *fully automatic* (solo mode only): `GAM_ENGINEERING_MERGE=auto`, `GAM_ENGINEERING_RELEASE_MERGE=auto`, merge guard removed; approval count and status hook unchanged. In team mode it refuses and offers `merge approved` instead. |
| `settings ask` | Preset *safe default*: `GAM_ENGINEERING_MERGE=ask`, `GAM_ENGINEERING_RELEASE_MERGE=ask`, merge guard restored. |
| `settings merge <ask \| approved \| auto>` | Set the merge policy; the merge guard is added for `ask` and removed otherwise. |
| `settings approvals <n>` | Set the approval count for `approved` (positive integer). |
| `settings branches <dev \| trunk>` | Switch the branch model (P-GIT-9): branches, MR targets, merge guard, and ROADMAP stage as [references/branches.md](../../gam-engineering/references/branches.md) says. Without git it refuses. |
| `settings release <ask \| auto>` | Set the release merge (P-MR-5). `auto` is refused in team mode, like `settings auto`. If the merge policy stays `ask`, say that the merge guard will still prompt at the release merge (P-MR-6). |
| `settings hook <on \| off>` | Add or remove the status hook (`hooks.Stop` and `gam-engineering/tools/status-reminder.mjs`). |
| `settings limit <on \| off \| <warn>/<stop> \| action <auto \| ask>>` | The limit guard (P-WS-12): `on` sets `env.GAM_ENGINEERING_LIMIT_GUARD=on` and adds the `statusLine` (`gam-engineering/tools/limit-statusline.mjs`) and the `PostToolUse` and `UserPromptSubmit` hooks (`limit-guard.mjs`), copying both scripts when missing; `off` sets the key to `off` and removes the three entries; `<warn>/<stop>` (for example `85/92`, integers with warn < stop ≤ 100) sets `env.GAM_ENGINEERING_LIMIT_WARN` and `_LIMIT_STOP`. `settings limit action <auto \| ask>` sets `env.GAM_ENGINEERING_LIMIT_ACTION`: at the stop threshold `auto` runs `stopp` at once, `ask` asks with a pop-up first. A personal `statusLine` in `~/.claude/settings.json` is hidden by the project's while the guard is on; say so when one exists. |
| `settings coauthor <on \| off>` | Whether commits and MRs credit the AI (P-GIT-8). `off` sets `attribution` to `{ "commit": "", "pr": "" }`; `on` removes the key, so Claude Code adds its `Co-Authored-By` trailer and *Generated with Claude Code* line. |
| `settings flow <full \| quick>` | Set `env.GAM_ENGINEERING_FLOW` (P-FLOW-1, [Quick mode](../../gam-engineering/references/quick.md)). `quick` is the plan flow with the slim pipeline (P-PIPE-3); the confirmation names what is no longer asked or run (concept, stories, issues, every check but the short test). `full` restores the standard flow. |
| `settings plans <on \| off>` | Add `plansDirectory: "./gam-ai-memory/plans"` or remove the key (P-DOC-7). `off` is a deviation from P-DOC-7 and is recorded as one (contract point 4). |
| `settings model <main \| judge \| draft \| check \| plan> <value> [<agent>]` | Set the main model a session starts on (top-level `model`) or a tier (`env.GAM_ENGINEERING_MODEL_JUDGE`, `_DRAFT`, `_CHECK`) or the plan key (`env.GAM_ENGINEERING_MODEL_PLAN`, default the judge value), see [Models](../../gam-engineering/references/models.md). `<value>` is `<model>` or `<model>:<effort>` (`opus`, `opus:low`, `gpt-6.2-sol:medium`), with a Claude alias or a full model ID; an effort other than `low`, `medium`, `high`, `xhigh`, or `max`, and anything that is neither an alias nor a plausible model ID, is refused. `default` removes the key. With `<agent>` (`codex`, `copilot`, `antigravity`; `gemini` is written as `antigravity`) the key gets its suffix (`GAM_ENGINEERING_MODEL_DRAFT_CODEX`, `GAM_ENGINEERING_MODEL_PLAN_ANTIGRAVITY`) and is written like the unsuffixed key (every model key is personal: the committed value is the project default, `settings local` writes one developer's override); without `<agent>` the key is the Claude one. `main` takes no agent. `settings model plan` without a value shows the native plan lever of the current agent for the developer to set: `opusplan` (Claude Code `model`), `plan_mode_reasoning_effort` (Codex), `planModel` (Copilot CLI), `chat.planAgent.defaultModel` (VS Code); a skill never writes an agent's own configuration file. Every change of the unsuffixed draft tier also sets `env.CLAUDE_CODE_SUBAGENT_MODEL` to the model part of the same value (the model of the subagents Claude Code starts by itself, [Models: Delegation](../../gam-engineering/references/models.md#delegation), Q575); `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` is never set. Setting `main` or `judge` below `opus` names the commands that recommend the judge tier (grill, setup, migrate, check, review, release, merge). The confirmation says that `/model` in a session still overrides `main` for that developer, and that judge commands then run by judge handoff ([Models: Handoff](../../gam-engineering/references/models.md#handoff)). |
| `settings delegate <files \| output> <n>` | Set `env.GAM_ENGINEERING_DELEGATE_MIN_FILES` (default `5`) or `env.GAM_ENGINEERING_DELEGATE_MIN_OUTPUT_LINES` (default `200`), the sizes above which a step goes to a subagent ([Models: Delegation](../../gam-engineering/references/models.md#delegation)); a positive integer, `default` removes the key. |
| `settings model command <command> <tier \| value \| default> [<agent>]` | Set `env.GAM_ENGINEERING_MODEL_<COMMAND>`, a tier (`judge`, `draft`, `check`) or a value `<model>[:<effort>]` that replaces the recommended tier of one command (`<command>` in upper case, `-` and spaces as `_`, e.g. `IMPLEMENT`); with `<agent>` the key gets the suffix of that agent (`GAM_ENGINEERING_MODEL_IMPLEMENT_CODEX`, personal like every model key); `default` removes the key ([Models: Tiers](../../gam-engineering/references/models.md#tiers), [Agents](../../gam-engineering/references/models.md#agents)). |
| `settings logs <n>` | Set `env.GAM_ENGINEERING_LOG_KEEP`, the number of script logs kept in `claude-script-logs/` of the temp folder before the oldest are deleted (P-WS-11); a positive integer, `default` removes the key (30). |
| `settings kind <student \| teacher \| normal>` | Set `env.GAM_ENGINEERING_PROJECT_KIND` (P-TEAM-6). `student` also sets the export to `commit` as `settings prompts commit` does, and is refused while the project is in stealth mode or has footprint `minimal` (`.gitignore` has the stealth or the minimal block); `teacher` and `normal` keep the export as it is. |
| `settings footprint` | Show `env.GAM_ENGINEERING_FOOTPRINT` (`tracked`, `stealth`, `minimal`; missing with `GAM_STEALTH_TARGET` set reads as `stealth`) with the paths it keeps out of git, from `node gam-engineering/tools/footprint.mjs show`. A change is never made here, since it changes the git index: `settings footprint minimal` and `settings footprint stealth` route to [`migrate minimal`](migrate-minimal.md) and [`migrate stealth`](migrate-stealth.md) (stealth only from `tracked`: it refuses under `minimal`); back to `tracked` there is no command yet (README *Footprint*, A10, A12). |
| `settings prompts <commit \| local>` | Set `env.GAM_ENGINEERING_PROMPT_EXPORT` (P-TEAM-6); `local` is refused in a `student` project, `commit` under footprint `minimal`, where `docs/prompts/` is ignored (A11). Both copy `prompt-export.mjs` when missing and run its `install-hook`; `local` adds `/docs/prompts/` to `.gitignore` and removes the custom check `check-growth` from `pipeline.json`, `commit` records it. Already committed exports stay. `off` is refused: the export is the record of the question rounds (P-GRILL-2); a project that cannot use it records a deviation (`profile deviation P-TEAM-6`). |
| `settings local <key> <value \| default>` | Write a personal key (P-TEAM-2: the limit guard and session keys, `LOG_KEEP`, `FRONTEND_HOOK`, model tiers and per-command models, `DELEGATE_MIN_*`, `RUNNER`, `MAX_PARALLEL`: `auto` or a number, the limit of parallel worktrees, [parallel.md](../../gam-engineering/references/parallel.md#how-much-parallelism)) to the git-ignored `.claude/settings.local.json`, for this developer only; `default` removes it there. `<key>` is the env name with or without the prefix `GAM_ENGINEERING_`. A project key is refused with the name of the command that changes it for everyone. Before writing, check `git check-ignore -q .claude/settings.local.json` and add the line to `.gitignore` when it fails. The file is never committed, so steps 3 and 4 below are skipped. |
| `settings runner <agent \| orca \| t3>` | Set `env.GAM_ENGINEERING_RUNNER` (Q475, QA0024–QA0028, P-WS-13): who builds the issues of `implement-all`. Without the key, a T3 session (`CLAUDE_CODE_ENTRYPOINT` `t3-code` or `T3CODE_THREAD_ID` set) runs as `t3`, every other session as `agent`. `t3` starts T3 Code threads through `t3 thread start` ([implement-all: Runner t3](../../gam-delivery/references/implement-all.md#runner-t3)); setting it checks that `t3 --version` answers, as for `orca`. `agent` (the default outside T3) starts Claude Code subagents in worktrees the session creates ([Worktrees for subagents](../../gam-engineering/references/parallel.md#worktrees-for-subagents)); `orca` starts Orca workers through `orca orchestration` ([implement-all: Runner orca](../../gam-delivery/references/implement-all.md#runner-orca)). Setting `orca` checks that the `orca` command answers and says so when it does not; `implement-all` then falls back to `agent`. |
| `settings frontend <on \| off>` | Set `env.GAM_ENGINEERING_FRONTEND` (P-DES-13, Q478): `on` (default) makes `gam-frontend` mandatory for every interface change; `off` lets the commands skip it and names what is no longer called (`build`, `motion`, `review` from `implement`, `review` from `review`). `default` removes the key (`on`). A one-part override needs no setting: the developer names the other skill in the session. |
| `settings frontend hook <on \| off>` | Set `env.GAM_ENGINEERING_FRONTEND_HOOK` (P-DES-12, Q483, Q484): `on` makes the PostToolUse hook `frontend-hook.mjs` run the impeccable detector on every edited interface file and name `gam-frontend` once per session; `off` (default, also when the key is missing) keeps it silent. Same as `/gam-engineering frontend hook <on \| off>`; `frontend hook status` shows the state ([frontend.md](frontend.md#frontend-hook)). |
| `settings session <percent>` | Set `env.GAM_ENGINEERING_SESSION_THRESHOLD`, the context fill above which a new session is suggested and the Stop hook `compact-hint.mjs` says to run `/compact` before a pause (again at every further 10 points) ([Models: Session length](../../gam-engineering/references/models.md#session-length)); an integer from 10 to 90, `default` removes the key (50). |
| `settings session hours <n>` | Set `env.GAM_ENGINEERING_SESSION_MAX_HOURS`, the session age in hours after which the hook `limit-guard.mjs` recommends once to save with `stopp` and continue in a new session (P-WS-12, [Models: Session length](../../gam-engineering/references/models.md#session-length)); a number, `0` turns the hint off, `default` removes the key (4). |
| `settings skills <on \| off \| keep <list \| default>>` | The skill trim (P-WS-7): `on` or `off` sets `env.GAM_ENGINEERING_SKILL_TRIM` (SessionStart hook `skill-trim.mjs`, which writes `skillOverrides` `user-invocable-only` for the skills the project does not need into `.claude/settings.local.json`; `off` leaves entries already written alone and removes none, while `on` gives a skill that is needed again its listing back); `keep <list>` sets `env.GAM_ENGINEERING_SKILLS_KEEP`, a comma list of skill names that stay visible, `default` empties it. Both keys are personal, `settings local` writes them for one developer. Entries are removed with `/skills`. [Models: Session length](../../gam-engineering/references/models.md#session-length). |

Steps for every change:

1. Show the change as *key — old → new*, including the safeguards it adds or removes, and confirm it with an `AskUserQuestion` pop-up (*Apply* / *Cancel*); a loosening change (towards `approved` or `auto`, guard or hook removed) also names what will no longer be asked.
2. Edit `.claude/settings.json` without touching any other key, and `WORKFLOW.md` only if a pointer to the changed keys is missing — it never holds the values.
3. Under footprint `minimal` the file is git-ignored (P-MR-4, A7): the edit on disk is the whole change, with no branch or MR; go on with step 4. Otherwise ship it like any change: on the current work branch, or on a new `chore/settings-<slug>` branch from `dev` with an MR (P-GIT-2). The MR merges under the policy currently on `dev`, not the new one. Without git the edit is the whole change, and the merge keys have no effect until the folder is a git repository (P-GIT-7).
4. Add a log entry in `ROADMAP-DETAILS.md` (P-ROAD-2).

## Safeguards

The settings template carries two technical safeguards; this table is their single description, and the README links here:

| Safeguard | What it does | When it is present |
| --- | --- | --- |
| Merge guard (`permissions.ask`, P-MR-6) | Six rules — `git merge`, `glab mr merge`, `gh pr merge`, each for Bash and PowerShell — make Claude Code itself prompt before a merge command, as a backstop if an agent skips the pop-up | Only under merge policy `ask` |
| Status hook (`hooks.Stop`) | Runs `gam-engineering/tools/status-reminder.mjs` ([template](../../gam-engineering/templates/gam-engineering/tools/status-reminder.mjs)) with Node at the end of each turn. First it reads the session transcript and blocks once when the last line contradicts the run status (P-WS-9): `Fertig` while a background run of the session has not reported its end or a log in `claude-script-logs/` the session named has no `exit code` line, a turn opened by the completion notification of the session's own run that ends without continuing (stale `Läuft noch` or no line), or a message without a status line. Then it passes when the newest merge on the integration branch (`dev` or `origin/dev`; `main` or `origin/main` in branch model `trunk`) touched `ROADMAP-DETAILS.md` or a `STATUS.md`, when a later commit on that branch or on `HEAD` did, or when one of them is modified in the working tree, or when every commit the merge brought in carries `[no-req]` among the tags ending its subject, also before further tags such as `[guide-ok]` (a pure chore); otherwise it blocks the stop once and asks for the P-ROAD-4 update. If `gam-ai-knowledge/` is outside git, it compares the file time with the merge time | Always. Needs Node; the second stop always passes |

Open-work hook (`hooks.Stop`, P-GIT-11): runs `gam-engineering/tools/open-work-reminder.mjs` ([template](../../gam-engineering/templates/gam-engineering/tools/open-work-reminder.mjs)) at the end of each turn. It blocks the stop once per state when the working tree has changes, commits are not pushed, or a work branch is not merged into the integration branch (not under merge policy `auto`, which merges without a pop-up), and asks the agent to check what else is open and to ask with a pop-up; a branch without an upstream counts only commits no remote has, and in an Orca session the pop-up is asked under `auto` too (Q583); `settings hook off` removes it together with the status hook.

Under `ask`, the merge guard prompts in addition to the P-MR-4 pop-up; the pop-up is the decision and the permission prompt only confirms it.
