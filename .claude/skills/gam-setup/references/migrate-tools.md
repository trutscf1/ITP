# Migrating the tooling

Parts 2 and 5 of [Migrating a project](migrate.md), loaded when its step 1 finds the old layout or tooling that is not current — through `/gam-engineering migrate`, or `migrate tools`, which checks only these two parts and the memory part 7 ([Memory check](memory.md#in-setup-and-migrate)). Detection order, the one confirmation, the branch, and the checks are in that file; this part holds only the actions.

The tooling part brings an existing project's tooling up to the current templates: what setup step 10 and its neighbours would copy today but the project lacks or has in an older version — for example the merge kit added on 2026-10-14. Documents in the knowledge folder (`gam-ai-knowledge/`, before the move `gam-engineering/documentation/`) are not touched except for `MANIFEST.md`, the two `WORKFLOW.md` pointers, the `STACK.md` parts and `test-data/README.md` of the rebuild (RB-F-32), and the path updates below. A concept document gains its three rebuild tables (*Persisted layout*, *Seed records*, *External contracts*) only when it is next changed (P-DOC-5, RB-F-32); this migration leaves it alone. It needs a project that has a goal (`GOAL.md` in the documentation folder; otherwise run setup or part 1 first); git, host, and mode are read as in [Projects without git](../../gam-engineering/references/no-git.md) and `WORKFLOW.md`.

## Old locations (part 2)

Before 2026-10-14 the documents lived in a top-level `documentation/` and the tooling was copied to generic paths that can collide with a project's own files. The documentation folder moves as a whole, straight to `gam-ai-knowledge/`, by part 6 ([migrate-knowledge.md](migrate-knowledge.md)), and `tools/doc-check.mjs` with it; each other tooling file that is the skill's copy — its header comment names `gam-engineering` (or a former name, `humanengineering` or `engineering-human`) — moves to its current path with `git mv` (without git: a plain move):

| Old path | New path | Also update |
| --- | --- | --- |
| `tools/merge.ps1`, `tools/MERGING.md` | `gam-engineering/tools/` | Remove `tools/` only if it is empty afterwards; a project's own files there stay. |
| `.gitlab/ci/docs.yml` | `gam-engineering/ci/gitlab-docs.yml` | The `include` in `.gitlab-ci.yml`. |
| `.github/workflows/docs.yml` | `.github/workflows/gam-engineering-docs.yml` | — |
| `.claude/hooks/status-reminder.mjs` | `gam-engineering/tools/status-reminder.mjs` | The `Stop` command in `.claude/settings.json`. |

Then replace the old paths in every project file that names them (`CLAUDE.md`, `README.md`, `gam-ai-knowledge/`, scripts, CI), found with `git grep -n -e "tools/merge" -e "tools/MERGING" -e "status-reminder.mjs" -e "ci/docs.yml" -e "workflows/docs.yml"`; closed issues, old commits, and log entries are not rewritten. Ignore lists name folders, not files: wherever `.gitignore`, `.deployignore`, or a similar list excludes `tools/`, add `gam-engineering/` next to it (keep `tools/` while the project still has files of its own there), so the moved tooling is not published or deployed where it was not before. A file at an old path that is not the skill's copy is left alone and listed. Until a project is migrated, the commands of this skill read the documents from `documentation/` where neither `gam-ai-knowledge/` nor `gam-engineering/documentation/` exists, run `doc-check` from `tools/doc-check.mjs` (with the path `documentation`) where no newer copy exists, and offer `migrate` once.
