# New project setup

Loaded by `/gam-engineering setup` (skill `gam-setup`).

For a fresh repo that should follow the user's standard process:

1. **Create the knowledge folder and define the project goal.** Run [gam-ai-knowledge: Init](../../gam-ai-knowledge/references/init.md) (P-DOC-11): it asks the goal first — derived from the approved project application (*Projektantrag*, SMART goals) if one exists: one goal of at most 200 characters, target users, 1–3 measurable success signals, non-goals — and creates `gam-ai-knowledge/` with every knowledge document, `MANIFEST.md`, `tools/doc-check.mjs`, and the `AGENTS.md` pointer. Nothing else is created before the goal exists (P-GOAL-1). If the skill `gam-ai-knowledge` is not installed, stop with "Setup needs the skill gam-ai-knowledge; install it and run the command again".
2. **Ask solo or team** (as a `Q<n>`, see [Asking the developer](../../gam-engineering/SKILL.md#asking-the-developer)), and with git in the same round the branch model (P-GIT-9: **trunk** recommended for solo, **dev** for team) and the flow (P-FLOW-1: **quick** or **full**, recommended by the code size as in [Quick mode](../../gam-engineering/references/quick.md#entry-question)), and set up accordingly ([manifest: Team Mode](../../gam-ai-knowledge/templates/concept_authoring_manifest.md#team-mode)). In a folder without git, make the one offer of [Projects without git](../../gam-engineering/references/no-git.md) first; if it is declined, the mode is solo and is not asked, step 6 and the CI job of step 10 are skipped, and step 7 writes the settings template unchanged without its question.
3. Keep `gam-ai-knowledge/MANIFEST.md` as step 1 copied it from [templates/concept_authoring_manifest.md](../../gam-ai-knowledge/templates/concept_authoring_manifest.md).
4. Copy [templates/CLAUDE.md](../../gam-engineering/templates/CLAUDE.md) to the repo root and fill in the `[placeholders]`.
5. Configure the agent files the callable skills read — tracker commands and domain-doc layout in `gam-engineering/agents/` — per [references/setup-tracker.md](setup-tracker.md), and create the root `CONTEXT-MAP.md` from [templates/CONTEXT-MAP.md](../../gam-engineering/templates/CONTEXT-MAP.md) (P-DOC-2).
6. Set up the tracker per P-TRK-1. Ask for the host (GitLab or GitHub) as a `Q<n>`; on GitLab, run the tier check instead of asking for the tier (P-TRK-4), then copy [templates/gitlab/](../../gam-engineering/templates/gitlab/) to `.gitlab/` or [templates/github/](../../gam-engineering/templates/github/) to `.github/` (issue templates for epics, user stories, and bugs, MR or PR template), ask for the sprint mode (`dated` / `fixed` / `goal`, and the length for `fixed`, P-TRK-1) as one `Q<n>`, create the labels and the first sprint milestone in that mode's form (on GitHub also the Project board), protect `main` and `dev` (in branch model `trunk` only `main`, with the approvals in team mode), and allow only merge commits (no squash, no rebase). For merge policy `approved`, also require `GAM_ENGINEERING_APPROVALS` approvals on `dev`.
7. Ask for the merge policy (`ask` / `approved` / `auto`, P-MR-4), the approval count, and the release merge (`ask` / `auto`, P-MR-5) as one `Q<n>`, and in the same round whether commits and MRs credit the AI (P-GIT-8; options **No** (recommended) and **Yes**), then write `.claude/settings.json` from [templates/claude/settings.json](../../gam-engineering/templates/claude/settings.json) — the `attribution` key for *No* or no `attribution` key for *Yes*, the `model` key and the two model tiers with their template values (stated as an assumption, changed later with `settings model`), `plansDirectory` set to `./gam-ai-memory/plans` (P-DOC-7), the three merge `env` values, `GAM_ENGINEERING_BRANCHES` and `GAM_ENGINEERING_FLOW` from step 2, the merge guard only under `ask` (plus its trunk rules in branch model `trunk`, P-MR-6), and the `Stop` hook — and copy [templates/gam-engineering/tools/status-reminder.mjs](../../gam-engineering/templates/gam-engineering/tools/status-reminder.mjs) to `gam-engineering/tools/`, where the `Stop` hook calls it (it runs with Node on every platform). If the settings file exists, merge into it without dropping other settings.
8. Fill the process documents step 1 created in `gam-ai-knowledge/`: [ROADMAP.md](../../gam-ai-knowledge/templates/ROADMAP.md) (add the planned features, if any), [ROADMAP-DETAILS.md](../../gam-ai-knowledge/templates/ROADMAP-DETAILS.md) (keep the solo or the team position section), [next.md](../../gam-ai-knowledge/templates/next.md) (solo; in team mode `team/<handle>/next.md` per developer instead), [WORKFLOW.md](../../gam-ai-knowledge/templates/WORKFLOW.md) (mode, host, labels, sprint mode, Definition of Done, release steps, time tracking on/off), [VERSIONING.md](../../gam-ai-knowledge/templates/VERSIONING.md), and the product backlog `work-items/BACKLOG.md` ([template](../../gam-ai-knowledge/templates/work-items/BACKLOG.md)), whose table stays empty (P-DOC-8).
9. Fill `gam-ai-knowledge/STACK.md` ([template](../../gam-ai-knowledge/templates/STACK.md)): §0, §1, and §8 now, the rest as the first concept reaches Phase 5. Fill in §10 now too, by step 2 of [Frontend](frontend.md). `CONTEXT.md`, `TEST_STRATEGY.md`, `DEPLOYMENT.md`, and `SECURITY.md` stay as step 1 created them until a concept or the architecture fills them.
10. Copy the documentation checks. Everything the skill copies into a project carries its name so it cannot collide with the project's own files: scripts and guides go to the folder `gam-engineering/` in the repo root, the CI job and the hook get the prefix `gam-engineering-`. The checker `gam-ai-knowledge/tools/doc-check.mjs` came with step 1; copy [templates/.markdownlint.jsonc](../../gam-engineering/templates/.markdownlint.jsonc) to the repo root. Then run [Pipeline](pipeline.md), steps 1–11 (under flow `quick`: [the short test and the architecture checks](pipeline.md#flow-quick) instead of steps 2–7; the checks are described in [Architecture checks](pipeline.md#architecture-checks)), which decides where the pipeline runs and which checks it runs and writes the host CI file, which holds the docs job (P-PIPE-1); its rounds belong to this setup, and its files ship with the setup commit. If the repo publishes itself, add the P-DOC-9 entries to its publish lists as in the *Publish lists* row of [Migrating the tooling](migrate-tools.md), stated as an assumption `A<n>`. If the project formats with Biome (`biome.json` or `biome.jsonc`), set it up as the *Biome on write* row of the same file says (P-DES-10), stated as an assumption `A<n>`. Run `node gam-ai-knowledge/tools/doc-check.mjs` once; on the fresh documents it must exit with 0 and report no `PUBLISH-LEAK`. With git, also copy the manual merge kit: [templates/gam-engineering/tools/merge.ps1](../../gam-engineering/templates/gam-engineering/tools/merge.ps1) and [templates/gam-engineering/tools/MERGING.md](../../gam-engineering/templates/gam-engineering/tools/MERGING.md) to `gam-engineering/tools/` — the guide and script for merging into `dev` and releasing to `main` without an agent (*I merge myself*, P-MR-4). Then run [AI chat export](#ai-chat-export), and write `gam-engineering/version.json` with the highest entry of [migrations.md](migrations.md) ([migrate.md: Step 5](migrate.md#step-5--version)).
11. **Create the short-term memory.** Run the setup part of [Memory check](memory.md#in-setup-and-migrate): with gam-ai-memory installed and current, `/gam-ai-memory init` always runs and creates `gam-ai-memory/` or completes an existing one; otherwise print its hint line and name `/gam-ai-memory init` as an open step in the summary (P-DOC-12).

The templates are the reusable versions of the `gamaiconcept` originals; that project remains their reference implementation for everything except the goal, human-readability, team, git-host-workflow, merge-policy, and model-setting rules added here (the knowledge templates of gam-ai-knowledge, CONTEXT-MAP, `.markdownlint.jsonc`, `gam-engineering/`, `claude/settings.json`, `claude/hooks/`, `agents/`, and the `gitlab/` and `github/` templates are new).

## AI chat export

Part of step 10 (P-TEAM-6, P-GRILL-2): the export is the record of every question round, so every project gets it. Copy [templates/gam-engineering/tools/prompt-export.mjs](../../gam-engineering/templates/gam-engineering/tools/prompt-export.mjs) to `gam-engineering/tools/`. Ask one `Q<n>`: whether this is a student project (`student` / `other`), and, in the same round, where the exported chats stay — **commit** (into the repo; recommended for `student`) or **local** (only on each computer, `docs/prompts/` in `.gitignore`; recommended otherwise). Write `env.GAM_ENGINEERING_PROJECT_KIND` and `env.GAM_ENGINEERING_PROMPT_EXPORT` to `.claude/settings.json`. With git, run `node gam-engineering/tools/prompt-export.mjs install-hook` yourself, never ask the developer to (it sets `core.hooksPath .githooks` or appends to the hook a project already has, makes the hook executable, and stores the GitHub or GitLab user name in the local git config), and check that `core.hooksPath` points to the hook folder and the active `pre-commit` holds the marked line. If it prints `prompt-export: username unknown`, ask one `Q<n>` for the user name and set it with `install-hook --username <name>`. Only if the command cannot run (no Node 22.13, refused), name the reason and the command for the developer to run. Each clone needs it once: when `package.json` has no `prepare` script, add `"prepare": "node gam-engineering/tools/prompt-export.mjs install-hook"`, stated as an assumption `A<n>`; otherwise name the command in `README.md`. Copy the section *AI chat export* of [templates/CLAUDE.md](../../gam-engineering/templates/CLAUDE.md#ai-chat-export) into every agent instruction file the repo has (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.github/copilot-instructions.md`, `.cursor/rules/`), replacing an older copy of the section instead of adding a second one; without any, `AGENTS.md` is created with it. Without git there is no hook; `stopp` runs `export`. With **commit**, record the check `{ "kind": "custom", "language": "", "tool": "node gam-engineering/tools/prompt-export.mjs check-growth", "threshold": "", "native": false, "ciImage": "node:24" }` in `gam-engineering/pipeline.json` (it only warns). Name in the summary that in a school project the school management decides whether students' chats may stand in a public repo.
