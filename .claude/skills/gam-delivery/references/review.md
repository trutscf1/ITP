# Review

Loaded by `/gam-engineering review <MR>` (skill `gam-delivery`):

1. Call `gam-v-code-review` with the MR's merge base on `dev` as the fixed point, under override 5 of [gam-delivery](../SKILL.md#overrides-for-the-delivery-skills).
2. Add the two profile axes: every acceptance criterion of the issue (met / not met, with the test that proves it) and every Definition of Done item (met / not met). Read the guard report of the local pipeline (`gam-engineering/reports/`, check `guard`, P-PIPE-7) for Definition of Done item 2 (no check skipped without a written reason): a hit without a line in `gam-engineering/guard-reasons.md` is not met, and a reason line that does not justify the loosening is a finding. If the MR changes the interface, a criterion the interface shows is met only with the running-app evidence of P-DES-8; re-run it with the running-app skill from `STACK.md` §10 when the MR has none. Check the screenshots for legibility in every theme and the diff for fixed color values outside the token definitions (P-DES-9).
   Then list the behavior the criteria are silent on (empty input, duplicates, an interrupted operation) and judge each item in one line: covered by a test, handled in the code without one, or unhandled (SP-13).
3. Call the Skill tool with every other skill `STACK.md` §10 binds to `review` for a situation the MR touches (P-DES-7), and add its findings as a further axis.
4. If the MR touches stored data (a record, an index, a migration), check the diff against `STACK.md` §11 as a further axis: stored names, migration files, and the migration state in §11 agree with the change.
5. If the MR adds or upgrades a dependency (the lockfile or manifest diff), check it as a further axis: it is named in `STACK.md` (P-DES-4), fixed in the same MR if not (P-GIT-5); a new one states its reason and why the stack's existing tools do not cover it; an upgrade names the changelog entries it brings. More than one direct upgrade in one MR is a finding; a pure upgrade is a `chore/<slug>` branch of its own.
6. Report the result as a table, every finding labelled *Critical*, *Required*, *Optional*, *Nit*, or *FYI* (SP-7). Posting it as an MR comment follows override 6 of [gam-delivery](../SKILL.md#overrides-for-the-delivery-skills) — except under merge policy `auto`, where posting the clean result is the recorded review that P-MR-2 requires.

A `rebuild/<date>`, `chore/rebuild-doc-fixes-<date>`, or `chore/rebuild-drill-<date>` branch has no issue (RB-F-10, RB-F-40): in step 2 the criteria are the green check of [rebuild.md](../../gam-rebuild/references/rebuild.md#green-check) (RB-F-9) for a `rebuild/` branch, or, for a `chore/` branch, that its commits change documents only (the drill's: one log row in `ROADMAP-DETAILS.md` and its inbox items); the Definition of Done items on issues and story status are skipped, and the report names that.
