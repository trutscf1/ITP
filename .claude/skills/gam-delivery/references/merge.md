# Merge

Loaded by `/gam-engineering merge <MR>` (skill `gam-delivery`, manifest Phase 7, step 4) — the only path by which an agent merges into `dev`:

1. Check P-MR-3 with `gam-v-verification-before-completion` (override 7 of [gam-delivery](../SKILL.md#overrides-for-the-delivery-skills)): all acceptance criteria, every Definition of Done item, green pipeline, no unresolved threads. If anything fails, report it and stop; no merge prompt is offered. For unresolved threads on the agent's own MR, offer [revise](revise.md). The pipeline is green only when it is green at every location `location` names in `gam-engineering/pipeline.json` (P-PIPE-2):
   - **When it is due (P-PIPE-8):** run `node gam-engineering/tools/pipeline.mjs due merge-dev` (`merge-main` for a merge into `main`, with `--trunk` in branch model `trunk`). A location that prints `false` is not due at this merge: skip its bullet below and state `pipeline not due at <moment> (P-PIPE-8)`; it counts as green. The `release` command runs both pipelines whatever the answer.
   - **`local` or `both`:** with the work branch checked out and a clean working tree, first make sure the branch contains the integration tip (`git merge-base --is-ancestor <integration branch> HEAD`; where a remote exists, `git fetch origin <integration branch>` first): if it does not, merge the tip into the work branch, resolve conflicts there, and push, so the pipeline runs on the state the merge will produce; then run `node gam-engineering/local-pipeline.mjs` fresh in this check; an earlier run never counts; a check the runner reports as skipped by P-PIPE-3 or P-PIPE-6 (documents only) counts as green, and the report `report.md` in the newest folder of `gam-engineering/reports/local-pipeline/` (`<yyyy-MM-dd-HHmmss>`, PP-F-28) must be written after this step started. A non-zero exit is red: name every check run of that report that is not `passed`, with its detail, or its one line when it holds no table.
   - **`host` or `both`:** the MR's host pipeline for its head commit has succeeded (GitLab: `glab mr view <MR> -F json`, `head_pipeline.status` is `success` and `head_pipeline.sha` is the MR's `sha`; GitHub: `gh pr checks <MR>` all pass). A running pipeline is not green yet: wait until it ends.
   - **`none`:** no pipeline is recorded: the pipeline item is met without running or reading one, and the check says "no pipeline recorded" (PP-F-4); every other item, doc-check included, is still checked.
   - **Without `pipeline.json`:** the pipeline is the project's CI. A `pipeline.json` that doc-check reports as `PIPE` is red.
2. Apply the effective merge policy (P-MR-4, read per [Merge policy](../SKILL.md#merge-policy)): under `ask` show the pop-up; under `approved` count the approvals on the host (the project's `gam-engineering/agents/issue-tracker.md` has the command) and leave the MR pending if they are not enough; under `auto` run [review](review.md) first if no clean review is recorded yet (a branch built by [implement-all](implement-all.md) already carries the session's one review),; no pop-up even when the **Door** line says one-way (P-MR-4, changed 2026-11-03).
3. Merge with a merge commit (P-GIT-3) and delete the work branch (P-GIT-2). A status and a sync that step 4 puts on the work branch are committed before this step.
4. Status in the same working step (P-ROAD-4): if the MR did not already carry it, update the position row, the ROADMAP stage (`in dev`, or `merged` in branch model `trunk`, once the epic's last story is merged), and the story's `status: done` with `BACKLOG.md` and its sprint file (P-DOC-8) now; close the issue if the host did not (GitLab and GitHub close issues automatically only on the default branch), and the epic issue once its last story issue is closed; add the log entry. Then the memory sync (P-DOC-13):
   - **When:** a project whose `gam-ai-memory/` holds a memory (`CLAUDE.md`, `README_AI.md`, or a running file) and that has no `team/TEAM.md`; otherwise skip silently. With parallel sessions only the merging session syncs, after it folded the branch file in ([Parallel sessions](../../gam-engineering/references/parallel.md)).
   - **How:** call the Skill tool with `gam-ai-memory` and `sync`. When the installed skill has no command `sync`, follow `gam-ai-memory/prompts/sync.md` of the project; where that file is missing too, print the last hint line of [Memory check](../../gam-setup/references/memory.md#the-hint-line) once and go on.
   - **Where it is committed:** for a local merge, or an MR that carries the status, in the status commit on the work branch, before step 3 merges it (so in this case the status and the sync are written before step 3); for a host merge of an MR without the status, in the status commit on the integration branch after the merge. Never in a branch or merge of its own.
   - **Footprint `minimal`:** the status and memory files are git-ignored, so they are written on disk and belong to no commit; the merge carries only the code.
   - **Closing check:** `node gam-ai-knowledge/tools/doc-check.mjs --status` on the integration branch must report no `STATUS` error and, unless the hint line was printed, no `MEMORY` error.
5. **Copy the gam- folders (stealth mode).** Only after a merge of step 3 in this run, and only under footprint `stealth` (`node gam-engineering/tools/footprint.mjs show`); under `tracked` and `minimal` skip silently, since minimal keeps no copy (QA0049). Run `node gam-engineering/tools/stealth-backup.mjs` from the project root once step 4 is written, so the copy holds the merged state. Exit code 2 means not configured and is a note. Any other failure is reported loudly as `stealth-backup FAILED` with its message, and the merge stays done: a copy error never aborts or undoes a merge.
6. Name every MR left open (*Later*, missing approval) as pending in the session summary.
7. **Clean up after the merge.** Only after a merge of step 3 in this run, where the project has `gam-engineering/tools/worktree-cleanup.mjs`; otherwise skip silently. Run [cleanup](cleanup.md) with its pop-ups (QC0009): it removes merged, clean, idle worktrees and merged work branches of other sessions, never the worktree this session runs in.
8. **Remove the own worktree.** Only after a merge of step 3 in this run, when the session runs in a linked worktree (`git rev-parse --git-dir` differs from `--git-common-dir`) on the branch it just merged; otherwise skip silently. Write the closing message with the run status first, then remove the worktree as [Parallel sessions: Cleanup](../../gam-engineering/references/parallel.md#cleanup) says (QA0004–QA0006): never `--force`, uncommitted or untracked files stop it with one `Q<n>`, and in an Orca workspace the removal ends the session, so it is the last call.

## Rebuild and `chore/rebuild-doc-fixes-` branches

A `rebuild/<date>` branch, the `chore/rebuild-doc-fixes-<date>` branch of [rebuild.md](../../gam-rebuild/references/rebuild.md#keep-the-documentation-fixes), and the `chore/rebuild-drill-<date>` branch of [rebuild-drill.md](../../gam-rebuild/references/rebuild-drill.md#report-and-record) have no issue and no story (RB-F-10, RB-F-40): in the steps above, step 1 checks the green check of [rebuild.md](../../gam-rebuild/references/rebuild.md#green-check) in place of the acceptance criteria (a `chore/` branch: its commits are documentation only), the pipeline, and the threads; step 4 skips every issue, epic, story-status, and `BACKLOG.md` step and updates only the position row and the log entry, and still syncs the memory. The MR title is `Rebuild from documentation (<YYYY-MM-DD>)`; for the drill branch it is `Rebuild drill (<YYYY-MM-DD>): <verdict>`.

**Frozen check** (RB-F-11, RB-E-7), before step 2 and under every merge policy, for a `rebuild/` branch only:

1. Take `recordedHead` from `node gam-engineering/tools/rebuild.mjs plan --integration <integration branch>` (the parent of the branch's first commit).
2. Where a remote exists, run `git fetch origin <integration branch>`.
3. Compare `git rev-parse <integration branch>` and, where a remote exists, `git rev-parse origin/<integration branch>` with `recordedHead`. When either differs, merge nothing, offer no merge prompt, and report the new commits: `git log --format="%h %s" <recordedHead>..<that head>`. The developer decides on a new rebuild from the new head.
4. Under *I merge myself* the MR description already names `recordedHead` and says that the merge is wrong once the integration branch moved; hand over the MR link only after this check passed.

Without git, `merge <issue>` is the close step of [Projects without git](../../gam-engineering/references/no-git.md): step 1 without pipeline and threads, no step 2 and 3, then step 4.
