In `turbo.json`, the lint task is `"lint": {}`, so each package's lint fingerprint (Turborepo's hash) only covers that package's own files. The only Biome config is the root `biome.json`, which isn't in any package. Biome also reads the root `.gitignore`, because `useIgnoreFile` is on.

I checked this with a `--dry=json` run before and after adding a byte to `biome.json`, then put the file back. The hashes for `@stash/web#lint` and `@stash/identity#lint` didn't change. So if an MR turns on a stricter rule that existing code breaks, CI will show `cache hit, replaying logs` and lint will go green. That gets past the "pipeline must be green" merge gate. **Fix:** set `"lint": { "inputs": ["$TURBO_DEFAULT$", "$TURBO_ROOT$/biome.json", "$TURBO_ROOT$/.gitignore"] }`, or add both files to `globalDependencies`. Add a test for it next to `tests/ci-pipeline.test.ts`.
