**The `commit-messages` CI job fails on every push to `dev`** (`.gitlab-ci.yml:149-162`)

- **Cause:** on a branch pipeline the job uses `base = git merge-base HEAD origin/$CI_DEFAULT_BRANCH`. When the pipeline runs on `dev` itself, `base` is the same commit as `HEAD`. This happens after every MR merge and after a back-merge from `main`. It also happens when someone pushes a new branch that has no commits of its own yet.
- **Effect:** commitlint 21 does not accept an empty range. I checked locally: `pnpm exec commitlint --from HEAD --to HEAD` stops with "Invalid input flags: --from and --to point to the same commit" and exits with code 9. So `dev` goes red after every merge.
- **Fix:** add a rule that skips the job when `$CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH`. Also add a check in the script: if `base` and `HEAD` are the same commit, exit 0. Then add a case to `tests/ci-pipeline.test.ts` so the check stays in place.
